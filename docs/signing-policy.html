Code Signing Policy

Last updated: October 1, 2026

What is signed

Every Windows installer (CloudSync-Setup-*.exe) published on the GitHub releases page is Authenticode code-signed before release. The signature lets Windows verify the installer genuinely comes from this project and has not been tampered with.

How signing works

  • Release installers are built by GitHub Actions from the public source at github.com/avandever/openlp-cloudsync. No binaries are ever signed from a developer's local machine.
  • Signing is performed by the SignPath Foundation free code-signing service for open-source projects. The certificate is held in SignPath's hardware security module; the project maintainer never handles the private key.
  • SignPath verifies that each submitted binary was produced by the project's own GitHub Actions build before signing it.
  • Signatures are timestamped, so they remain valid after the certificate itself expires.

Publisher identity

Signed installers show SignPath Foundation as the publisher. This project (OpenLP Cloud Sync, by Andrew Vandever) does not hold its own code-signing certificate; identity is vouched for by the SignPath Foundation under its terms for open-source projects.

Verifying a download

Right-click the installer → Properties → Digital Signatures. You should see a signature from SignPath Foundation with a valid timestamp. If the signature is missing or invalid, do not run the file — download it again from the releases page above and report the problem on GitHub.
